- A push to master deploys the Node image to production (`.github/workflows/deploy.yml`, gated by `npm test` only). The Rust image job in the same workflow also needs the `check` job (Rust fmt/clippy/tests incl. golden parity) and only pushes `anime-kitsu-rs:<sha>`; it is not deployed until the cutover. `ci.yml` runs `test` and `check` on pull requests and non-master branches.
- Running locally: modules throw at load without `FANART_APIKEY`; `NO_CACHE=true` skips Mongo/memory caching.
  Load env with `export $(grep -E '^FANART_APIKEY=' .env | xargs)`; never print `MONGODB_URI`.
- Caches: in-memory LRU → Mongo (`kitsu_collection`) → Cloudflare (12h). Check the backend with `?<timestamp>` on the URL;
  keyv stays on 5 (cache-manager 7 can't read keyv 6 entries, see `test/cache.test.js`).
- Mapping rows (`static/data/imdb_mapping.json`, `new_mappings.json`): read `mapping/README.md` before researching or adding any.
- Search: `lib/title_search.js` ranks `static/data/search_titles.jsonl` (rebuilt weekly by `mapping/update_search_titles.js`);
  below `MIN_CONFIDENCE` it returns nothing. Check ranking changes with `node search_eval/evaluate.js` (offline).
  Names search can't work out go in `static/data/search_aliases.json` (kitsu id → titles; user-approved only).

## Rust port (`crates/`)
- Cargo workspace: `crates/kitsu-search` (ranking engine, no I/O) and `crates/kitsu-addon` (axum runtime, the Rust replacement of
  the Node addon). Toolchain pinned in `rust-toolchain.toml`; CI and `Dockerfile.rust` use the same version.
- Check: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --release`.
- Parity tests compare against Node goldens in `search_eval/golden/` (git-ignored; generated by `FANART_APIKEY=test NO_CACHE=true node search_eval/golden/dump.js`,
  see `search_eval/golden/README.md`). Missing goldens fail the tests unless `KITSU_GOLDEN_OPTIONAL=1` is set.
- The gate is the same ranked ids, order and confidence, not equal scores; no code is kept only to mirror JS. A Rust result may differ
  only where it is better, listed for owner review from the `search_parity` failure output. Until cutover a rule change goes into
  `lib/title_search.js` and the Rust rules together, then the goldens are re-recorded. Tests over live `static/data` files may only
  assert invariants.
- Offline evaluation: `cargo run --release -p kitsu-search --bin evaluate` (counterpart of `node search_eval/evaluate.js`).
- Image: `Dockerfile.rust` (musl, data baked in `/home/app/static/data`), built with `Dockerfile.rust.dockerignore`.
- Rust-only env vars: `PORT`, `DATA_DIR` (default `static/data`), `KITSU_COLLECTION` (default `kitsu_collection`), `MEMORY_CACHE_MB` (384),
  `STORE_TIMEOUT_MS` (30000), `SEARCH_CONCURRENCY` (2), `SEARCH_QUEUE` (32), `META_DEADLINE_MS` (20000), `PARTIAL_CACHE_MAX_AGE` (600 s, cache life of a partial meta), `KITSU_URL`, `TOKIO_MAX_BLOCKING_THREADS`, `ADDON_URL`;
  shared with Node: `MONGODB_URI`, `METRICS_USER`, `METRICS_PASSWORD`, `FANART_APIKEY`, `CACHE_MAX_AGE`, `META_TTL`, `CATALOG_TTL`, `NO_CACHE`.
